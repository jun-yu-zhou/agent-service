# 招标初稿流式输出优化与定稿方案

确认日期：2026-10-03。本文用于主力开发机接续实施；当前仅保存计划，未实施业务代码修改。

## 一、已确认结论

初稿改为云端 Managed Agent 直接输出 Markdown 正文，后端接收、前端实时渲染，完成后保存 MySQL 并开放人工编辑。不再要求云端写 `.md` 文件后下载。

定稿与审核报告继续由云端生成两个 DOCX，并保持一起交付。暂不改为本地 Markdown 转 Word：模板来源包含数据库 HTML、用户上传 DOC、DOCX、PDF，本地转换尚未具备沿用不同模板样式的能力。

用户要求定稿章节层级、字体字号、段落与表格样式、页面设置与模板一致；允许人工补充后页数、分页位置和目录页码变化。报告没有模板，按报告排版规则生成。

人工确认稿是定稿的正文依据，提示词要求不改写正文；不增加严格正文等价校验，用户下载后可自行复核和编辑。

## 二、当前实现与关键事实

- `managedagent/ManagedAgentClient.java` 已订阅云端 SSE，但目前只收集文件产物并等待一轮结束。
- `managedagent/ManagedAgentEventParser.java` 当前解析 `mark_artifacts`、错误与会话结束事件，尚未提供初稿正文增量给前端。
- `procurement/tender/service/TenderDocumentAiService.java` 当前从产物中挑选 `.md`，下载后转为初稿字符串；定稿阶段在原会话提交人工稿并下载两个 DOCX。
- `procurement/tender/prompt/TenderDocumentPrompts.java` 当前要求初稿生成 Markdown 文件并标记产物，需要与云端指令同时调整。
- `skills/docx-format` 只保守整理已有 DOCX，不负责 Markdown 转换或恢复模板样式。它执行固定 OOXML 脚本和 LibreOffice/UNO 更新目录，返回 `success`、`partial`、`fallback` 等状态。
- 云端 formatter 只能保留其输入 DOCX 已有的样式；真正的模板保真取决于它执行前生成 DOCX 的步骤，不能仅凭启用 skill 判断保真。

## 三、初稿链路实施方案

### 1. 云端正文协议

- 修改本地请求及云端 Agent 指令：初稿直接输出完整 Markdown，不写 `.md` 文件，不调用初稿 `mark_artifacts`，不返回下载链接作为正文。
- 使用独立行 `<<<TENDER_DRAFT_BEGIN>>>` 和 `<<<TENDER_DRAFT_END>>>` 标识正式正文。标记自身不进入展示或持久化正文；过程说明不属于正文。
- 标记允许跨增量片段，解析器需缓存未完成的标记。只接收本轮 assistant 正文消息，过滤 reasoning、工具调用、工具输出和历史轮次消息。
- 如果 Agent 输出新一份正式正文，替换当前预览；最终以最后一份边界完整的正文为准。轮次结束但没有完整正式正文时，任务失败，不能把解释文字或未闭合正文当作成功结果。
- 云端系统指令不得同时强制初稿文件交付，否则本地请求无法消除写文件步骤。

### 2. 云端事件接收

- 在现有 SSE 订阅上启用 `event_deltas[]=message`。先确认当前 Java SDK 是否暴露增量订阅和事件结构；不足时仅补齐现有调用能力。
- 按本轮事件 ID、消息 ID、内容块索引累积增量，完整消息用于校准，不将完整消息再次追加到已累计正文。
- 正常结束仍依赖本轮会话结束事件，单条消息完成不等于整轮成功。
- 输入模板和结构化数据继续通过现有文件挂载传入。此次只取消初稿输出文件，不改变输入文件流程。

### 3. 后端任务与浏览器 SSE

- 保留现有创建任务、状态查询和结果查询接口；新增任务级 SSE 订阅接口，沿用当前控制器路径前缀，后缀使用 `/tasks/{taskId}/stream`。
- SSE 输出 `draft`、`status`、`complete`、`error` 四类事件。`draft` 携带当前完整正文快照，而非让前端再拼接云端增量；短间隔合并推送，避免频繁重绘长文档。
- 后端累计正文并保持当前任务快照；任务完成时先保存最终正文和完成状态到 MySQL，再发 `complete`。使用现有状态和结果模型，避免增加独立工作流。
- SSE 订阅不能触发第二次生成。多个订阅者只查看同一后台任务；连接结束时释放订阅资源，浏览器断线不取消云端任务。
- 重新订阅时先发送当前正文及状态，再发送后续更新；任务已完成时直接返回持久化结果并结束流。
- 保留结果查询用于页面刷新和流连接失败后的状态恢复。服务重启中断的任务按现有启动恢复机制明确失败；若没有恢复机制，补最小状态收口，不实现云端自动续写。
- 生成失败时保留已收到的半成品供只读查看，明确显示失败；禁止编辑、保存或定稿为完整初稿。用户主动创建新任务重新生成。
- 云端凭据、工具日志、内部挂载路径不通过正文事件暴露给页面。

### 4. 前端展示

- 创建任务后订阅正文流，生成期间编辑器只读，保存及定稿按钮不可用。
- 短间隔合并正文快照并渲染 Markdown，不在每个 token 到达时重建编辑器。
- 新正式正文替换预览；完成后以服务端最终正文为准，开放人工编辑。
- 页面关闭或断网不取消后台任务。重新载入任务恢复当前状态、正文和订阅。
- 失败半成品保留只读，展示可读失败原因；不自动重试付费生成。

## 四、定稿与报告的方案评估

### 当前选择：云端生成并下载产物

云端仍可读取原模板和项目资料，在同一会话提交人工确认正文，生成定稿 DOCX 和审核报告 DOCX，再走现有下载与存储流程。

理由：当前模板格式多样，要求沿用模板字体和布局。本地直接 Markdown 转 Word 会重建样式；把 `docx-format` 移到本地也无法弥补转换前已经丢失的模板信息。

限制：云端 Agent 仍可能在生成 DOCX 时写文件失败或反复重试，也不能天然保证模板一致。当前不把首轮优化扩大为定稿链路重写。

### 本地方案未来适用条件

只有在具备可重复执行的模板转换和样式映射能力后，才考虑本地接管定稿。例如保留原 DOCX 的样式与节设置、将人工正文插入对应章节，或明确限定可支持的模板格式。届时可以复用现有保守排版规则，而非依赖模型临时编写排版代码。

首轮不新增本地转换依赖、不安装 Office/LibreOffice、不重写 formatter。

### 交付与失败行为

- 两个文件继续一起交付，均生成并保存成功后才开放交付。
- 失败沿用现有整轮失败处理，不增加单文件重试、部分成功状态或复杂补偿机制。
- 保留 formatter 原有状态判断；`partial`、`fallback` 不得统一宣称完整排版成功。当前不扩展额外业务状态机。
- 定稿正文不由审核结果自动改写；报告用于用户查看。

## 五、验证与验收

1. 用脱敏事件样例验证增量拼接、完整消息校准、重复事件、正文标记跨片段、新正文替换、旧会话事件过滤及缺失结束标记。
2. 浏览器验证边生成边显示、生成期间不可编辑、完成后可编辑、断线重新订阅、已完成任务载入以及失败半成品只读。
3. 覆盖数据库 HTML 模板和用户上传 DOC、DOCX、PDF 模板，检查初稿完整且没有工具日志、过程说明或重复正文。
4. 对比改造前后首字时间、正文完成时间、总耗时、云端写文件失败次数。流式主要改善可见等待时间，取消初稿文件步骤的实际提速以测量为准。
5. 回归人工保存、定稿和两文件下载；抽查模板章节、字体、表格与页面设置，不增加逐字强校验。
6. 执行编译及必要的事件解析检查；付费云端全量回归由开发者主动运行，不自动调用。

## 六、实施顺序与边界

1. 核对当前 SDK 的增量事件能力，用脱敏样例确定事件结构和正文解析协议。
2. 同步修改云端指令与本地初稿请求，接通后端正文累积及 MySQL 最终保存。
3. 新增任务 SSE 接口，接入前端只读预览和完成后编辑。
4. 验证断线、错误及完成行为，再做实际模板样例测量。

此次只优化招标初稿链路，复用现有任务、会话、MySQL 和前端编辑器；不扩展投标流程，不改变定稿与报告一起交付的约定。云端指令和后端协议必须同步部署，避免正文协议与文件交付协议不匹配。
