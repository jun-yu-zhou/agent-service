# AI 辅助生成招投标文件：收缩版开发交接说明

## 1. 产品边界重新确认

当前实现超过实际需求。后续开发以以下两条最短闭环为准，不再增加独立的模型审查、自动修订和复杂任务阶段。

### 招标文件

结构化数据（必填） + DOCX 模板（可选） → AI 生成初版 → 人工补充和编辑 → 确认定稿 → 下载 DOCX/PDF。

### 投标文件

招标单位的招标文件（必填） → AI 生成初版 → 人工补充和编辑 → 确认定稿 → 下载 DOCX/PDF。

一致性检查只作为编辑页面上的辅助提示，不应成为必须执行的工作流阶段，也不应阻止人工定稿。

## 2. 当前代码现状

当前 `procurement` 包已经具备模型生成、IMM 正文提取、Redis 异步任务、语义审查、一次自动修订、版本管理、定稿、DOCX/PDF 导出、Swagger 和招标工作台。

主要问题：

- 招标输入以任意正文或 OSS 文件为主，尚未形成“结构化数据必填、模板可选”的明确请求契约。
- 审查和自动修订进入了主状态机，使简单的“生成—人工编辑—定稿”流程变复杂。
- 招标链路实现较完整，投标链路只有初稿生成和基础异步任务，两边能力不对称。
- `Tender*` 命名渗透到了版本、渲染和导出能力，后续复用到投标文件会产生重复代码。
- 页面展示了审查与自动修订操作，偏离当前产品重点。

## 3. 下一台电脑的改造顺序

每一步单独提交，先删减再补投标链路，避免继续扩大代码量。

### 第一步：收缩状态机和页面

保留状态：`PENDING`、`GENERATING`、`COMPLETED`、`FAILED`。定稿状态由版本的 `finalized` 字段表达，不再放入生成任务状态机。

从主流程移除：

- `review` 接口及页面按钮；
- `auto-revise` 接口及页面按钮；
- `REVIEWING`、`REVISING` 状态和相关原始稿/原始审查快照字段；
- 页面中的审查抽屉和审查轮询逻辑。

可以暂时保留底层审查方法，但不得从控制器和工作台暴露；确认无调用后再删除提示词和服务方法。

验收：用户创建任务后只需等待初版完成，然后直接编辑、保存版本、定稿和下载。

### 第二步：重做招标文件创建请求

新增明确请求模型，建议字段：

```json
{
  "structuredData": "必填；允许 JSON 对象或结构化文本",
  "templateOssUrl": "可选；DOCX 模板 OSS URL"
}
```

要求：

- `structuredData` 为空直接返回 HTTP 400；
- 未传模板时使用内置通用版式；
- 传模板时下载模板并渲染，模板解析或渲染失败要返回可读错误；
- AI 只补全文字内容，不虚构结构化数据中不存在的金额、日期、资格和评分；
- 初版完成后立即建立版本 1。

旧的正文预览接口可以先标记废弃，待新接口验证后删除；旧的“任意 OSS 招标来源文件生成招标文件”入口不再作为正式产品接口。

### 第三步：补齐最小投标文件闭环

投标创建请求只要求 `tenderDocumentOssUrl`。通过 IMM 提取招标文件正文，提取为空时明确失败。

生成初版时只生成需要供应商补充的响应框架：投标函、报价、资格响应、技术/商务响应、证明材料索引等；供应商自身信息、报价、证书、人员、业绩和签章必须使用待补充占位符，禁止模型虚构。

复用通用版本与导出能力，实现：

- 创建投标初版任务；
- 查询任务和结果；
- 保存人工版本；
- 确认定稿；
- 导出 DOCX/PDF。

不要重新加入自动审查和自动修订主流程。

### 第四步：抽取通用文档能力

在招标与投标闭环都可用后，再进行小范围重构：

- `TenderDocumentArtifactService` 改为通用 `ProcurementDocumentArtifactService`；
- Markdown → DOCX 和 DOCX → PDF 转换器由两类文档共用；
- Redis 中的版本存储按 `documentType + taskId` 区分；
- 招标和投标控制器保留各自清晰的业务请求，不强行合并为一个万能接口。

### 第五步：简化工作台

首页只保留两个入口：“生成招标文件”和“生成投标文件”。

统一编辑流程：创建任务 → 等待初版 → Markdown 编辑/预览 → 保存人工版本 → 确认定稿 → 下载 DOCX/PDF。

招标页提供结构化数据编辑框和可选模板 URL；投标页提供招标文件 URL。不要展示内部模型、IMM、Redis、审查阶段或自动修订概念。

## 4. 建议保留与删除的代码

建议保留：

- `ModelConfig` 的 prototype 模型获取方式；
- `ImmGateway` 和 URL 到 OSS 路径的解析能力；
- `ProcurementTaskRedisStore`，但缩减字段；
- `DocumentGenerationTask`、`DocumentVersion`、`DocumentArtifact`；
- Markdown DOCX 渲染、PDF 转换和 OSS 上传；
- Swagger 和统一 API 异常响应。

确认新流程可用后删除或降级：

- 招标、投标审查提示词和自动修订提示词；
- `reviewConsistency`、`reviseDraft` 及闭环审查工作流；
- 审查专用结果字段和一次自动修订限制；
- 只服务旧流程的测试类；
- 工作台的审查/自动修订 UI。

不要一次性删除全部旧代码。每完成一个新入口并通过浏览器验收，再删除对应旧入口，保证始终有可运行版本。

## 5. `application-local.yml` 配置

另一台电脑复制 `src/main/resources/application-local.yml.example` 为 `application-local.yml`，填写本地真实值。该文件已被 `.gitignore` 忽略，禁止提交。

```yaml
app:
  dashscope:
    api-key: "你的百炼 API Key"
    base-url: "公司的百炼兼容模式地址；使用公共百炼时填 https://dashscope.aliyuncs.com/compatible-mode/v1"
  oss:
    endpoint: "https://oss-cn-shenzhen.aliyuncs.com"
    region: "cn-shenzhen"
    bucket: "开发环境允许使用的 test- 前缀 Bucket"
    access-key-id: "你的 AccessKey ID"
    access-key-secret: "你的 AccessKey Secret"
  imm:
    endpoint: "imm.cn-shenzhen.aliyuncs.com"
    project-name: "IMM"
  bailian:
    knowledge-enabled: false
    workspace-id: ""
    knowledge-base-id: ""
  procurement-document:
    oss-output-prefix: "procurement-document/"
    generation-model: "qwen3.7-plus"
    max-concurrency: 4
    task-ttl-hours: 24

spring:
  data:
    redis:
      host: localhost
      port: 6379
      password: "本地 Redis 密码；无密码则留空"
```

说明：

- OSS Bucket、IMM 项目和 OSS 文件必须位于阿里云允许互访的账户、地域和权限范围内。
- 开发环境使用 `test-` 前缀 Bucket；不要把公司的正式 Bucket 写进公开配置。
- 当前收缩版流程不依赖法律知识库，因此 `knowledge-enabled` 保持 `false`。
- Redis 用于保存异步任务和人工版本；另一台电脑启动服务前必须先启动 Redis。
- 不要把 API Key、AccessKey、Redis 密码或带签名的 OSS URL 写入 Git 跟踪文件。

## 6. 启动与最小验收

1. 启动 Redis。
2. 配置本地 `application-local.yml`。
3. 执行 `mvn -DskipTests compile`。
4. 启动 Spring Boot 服务。
5. 打开 `/swagger-ui/index.html` 验证接口，打开 `/procurement-workbench.html` 验证页面。
6. 改造完成后的最终验收只走两条链路：
   - 结构化数据 + 可选模板 → 招标初版 → 人工编辑 → 定稿 → 下载；
   - 招标文件 URL → 投标初版 → 人工编辑 → 定稿 → 下载。

## 7. 提交边界

提交 Java 源码、公开 `application.yml`、`application-local.yml.example`、静态页面和 Markdown 开发文档。不要提交 `application-local.yml`、案例原件、带签名 URL、导出产物、Redis 数据或 IDE 配置。
