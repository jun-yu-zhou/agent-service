## 已确认的总体决策

- 招标文件和投标文件两条链路均实现，但按轮次逐步交付。
- 支持“招标大纲”和“结构化招标数据”两种招标输入。
- 投标文件输入为已确认的招标文件、供应商结构化数据和证明附件。
- 使用章节化富文本进行人工编辑；表格保留结构化数据。
- 每条原始要求都保留来源位置，并能追踪到生成章节和审查结果。
- 一致性审查后只自动修订一次，再执行第二次审查。
- 产物包括结构化 JSON、DOCX、PDF 和一致性审查报告，并上传 OSS。
- DOCX 使用通用占位符、循环表格和章节锚点协议；正式模板到位后通过模板映射适配。
- 首版包含 REST 接口和简易在线编辑页面。
- 模型必须从 `ModelConfig` 获取 prototype Bean，并记录模型输入 Token、输出 Token 和耗时。

## 第一轮：固化计划与工程基础

- 将本实施计划保存到案例资料目录。
- 引入 poi-tl；PDF 导出依赖在对应实现轮次单独引入并验证兼容性。
- 新建独立 `procurement` 业务包，不继续向实验性质的 `agile` 包堆积代码。
- 建立任务状态、文档类型、版本和产物等跨流程基础模型。
- 增加模板位置、OSS 输出前缀、生成模型和并发量配置。
- 验收：Maven 跳过测试编译通过。

## 第二轮：输入解析与统一需求模型

- 建立统一招标需求模型，包含项目基本信息、采购标的、预算、资格条件、技术参数、商务要求、评分办法、合同条款、附件格式及 ★/▲/普通等级。
- 每条需求保存唯一编号、原文、来源文件、来源位置、重要等级和目标章节。
- 实现结构化数据适配器，自动识别 UTF-8、GBK/GB18030，解析字符串形式的嵌套 JSON，并兼容空值及数字/字符串混用。
- 将案例数据中的 `Y/Z/N` 映射为 ★/▲/普通条款。
- 实现 DOC/DOCX 大纲适配器，复用 IMM 正文提取能力；程序校验预算、数量、评分合计、重复编号和关键字段缺失。
- 验收：两类案例均能输出统一需求模型和解析异常摘要。

## 第三轮：招标文件生成 Agent

- 新增招标生成专用提示词和 Agent。
- 按模板章节分段生成招标公告、投标人须知、合同条款、采购需求、评标办法和投标文件格式。
- 生成前建立“来源需求—目标章节”映射；预算、数量、期限、分值、★/▲标识由程序直接填充。
- 保存章节结构、来源需求编号、生成状态、输入/输出 Token 和耗时。
- 验收：两个案例均形成章节完整、顺序正确的结构化招标文件初稿。

## 第四轮：DOCX 模板渲染与 PDF 导出

- 定义 `{{field}}` 普通字段、循环表格标签和长章节锚点协议。
- 使用 poi-tl 渲染通用 DOCX 模板，保留标题样式、编号、页眉页脚、表格和分页。
- 使用 docx4j-export-fo 进行纯 Java PDF 导出，并以 `DocumentConverter` 隔离实现，允许以后替换为 LibreOffice 或公司转换服务。
- 上传 JSON、DOCX、PDF 到 OSS并返回下载地址。
- 验收：Word 可正常打开 DOCX，PDF 内容完整且核心版式无明显错位。

## 第五轮：招标文件一致性审查与自动修订

- 按资格条件、★/▲条款、技术参数、商务要求、评分规则、合同条款和模板格式建立逐条追踪矩阵。
- 每项包含原始要求、招标文件内容及位置、状态、偏差和修改建议。
- 金额、数量、日期、分值合计和标识优先使用确定性程序校验，语义一致性由模型判断。
- 首次审查后只修订异常章节一次，再执行第二次审查；不得篡改来源事实。
- 验收：预算错误、漏项、分值错误和 ★ 条款遗漏可被发现并修复。

## 第六轮：投标文件生成 Agent

- 解析招标文件、供应商信息、报价数据及证明附件，先形成响应矩阵再生成正文。
- 动态生成开标一览表、分项报价表、资格材料、技术/商务偏离表、实质性条款响应表、实施/培训/售后方案和证明材料索引。
- 禁止虚构企业、证书、报价、人员、业绩、签字和盖章；缺失内容形成结构化待办。
- 验收：初稿逐条响应招标要求，缺失材料可追踪，表格随项目要求动态变化。

## 第七轮：投标文件一致性审查与自动修订

- 逐项标记完全响应、部分响应、未响应或偏离。
- 检查资格、★/▲条款、技术商务响应、报价一致性、格式、签字盖章、证明材料和残留占位符。
- 只自动修改现有事实能够支撑的内容；资质、报价、材料和签章缺失仅进入待办。
- 验收：输出合规报告、风险清单和定稿前检查表，并通过第二次审查反映修订结果。

## 第八轮：REST 接口与任务编排

- 提供创建任务、查询进度、获取章节、保存人工版本、审查、自动修订、确认定稿和获取产物 URL 的接口。
- 长任务异步执行并返回任务 ID；失败时记录阶段和可读错误。
- 保存父版本、变更来源、修改人、时间和审查结果；一次工作流最多自动修订一次。
- 验收：REST 请求能够完成从输入到定稿下载的闭环。

## 第九轮：简易人机协同编辑页面

- 实现项目列表、任务进度和产物下载入口。
- 编辑页采用章节树、富文本编辑区、来源要求/审查问题面板，复杂表格单独结构化编辑。
- 支持保存版本、定位问题、接受或拒绝建议、复审、定稿和下载。
- 将主流程控制为上传与填写、生成并审查、确认并导出三个步骤。
- 验收：无需运行测试类即可在浏览器完成招标或投标文件生成。

## 第十轮：综合测试与竞赛验收

- 使用目录中的结构化数据案例和大纲案例做完整回归。
- 覆盖编码异常、输入缺失、超长需求、批量附件、预算/评分/★条款/报价冲突等场景。
- 统计耗时、模型调用次数、输入/输出 Token 和失败阶段。

- 按竞赛评分细则形成逐项验收清单。

## 跨轮次执行规则

- 每次只实现一轮，不提前混入后续业务功能。
- 开始前读取本计划和 Git 状态，保护用户未提交改动。
- 完成后更新本文件的状态、实际变更、验证结果、遗留问题和下一轮入口。
- 每轮至少执行 `mvn -DskipTests compile`；涉及业务行为时增加对应测试。
- 每轮结束汇报修改文件、验证结果和建议 Git 注释；未经明确要求不提交或推送。

## 案例资料结论

- 招标文档需完整覆盖公告/邀请、投标人须知、合同、采购需求、评标方法和投标格式，而非只生成正文片段。
- 投标文档需逐条响应资格、实质性、技术、商务和格式要求，并维护证明材料索引。
- 两类审查报告均以逐条追踪矩阵、分类统计和修改建议为核心。
- 结构化案例文件存在 GBK 编码、嵌套 JSON 字符串、空值和字段类型不一致，第二轮必须先规范化再交给模型。
- “深圳大学货物类招标文件模板”目前只是指向外部磁盘的快捷方式，仓库没有真实模板；首版按通用模板协议实现。

## 第八轮实施记录（2026-09-06）

- 新增招标初稿正文预览 REST 接口：直接接收来源正文，返回初稿和确定性检查结果，不持久化且不创建后台任务。
- 异步任务、版本、产物与下载接口仍按后续小步补充，避免首个 Web 接口承担全部任务编排职责。
- 接入 springdoc OpenAPI 2.1.0 并补充接口说明与请求示例；本地启动后已验证 `/swagger-ui/index.html`、`/v3/api-docs` 和预览接口登记均返回正常。
- 新增投标初稿正文预览 REST 接口：直接接收招标正文与供应商资料正文，返回 Markdown 初稿，不持久化且不创建后台任务。
- 新增招标初稿内存异步任务入口、状态查询和结果读取接口：任务只生成初稿与确定性检查，使用配置的最大并发数；重启服务后任务记录会丢失。
- 招标生成提示词禁止在已完整闭合的金额、数量、日期或评分项集合中额外添加“其他”待补充项。
- 确定性金额检查规范化千分位和无意义小数位，避免 `120,480元` 与 `120,480.00元` 等等值金额被误报为遗漏。
- 招标异步任务支持人工触发语义一致性审查：正文任务复用内存来源正文，OSS 任务重新提取正文；审查结果随任务结果接口返回。
- 任务结果接口在同一锁下读取任务、初稿与审查结果快照，避免审查结果已返回但状态仍显示为 `REVIEWING` 的并发中间态。
- 再次发起审查时先清空上一次审查结果，避免旧 `review` 与新一轮 `REVIEWING` 状态同时返回。
- 投标初稿新增内存异步任务入口、状态查询和结果读取接口；招标与投标任务共用一个受 `max-concurrency` 控制的线程池，避免总并发超出配置。
- 招标异步任务新增 OSS 文件入口：后台通过 IMM 提取正文后复用初稿生成与检查链路，提取失败或正文为空时任务明确失败。
- 投标生成提示词明确禁止将签字、盖章、日期输出为已完成状态，统一保留为待补充项。
- 投标生成提示词要求将供应商资料中已知字段一致回填到所有对应位置，避免与待补充标记冲突。
- 招标异步任务状态迁移至 Redis：任务状态、初稿、确定性检查、审查结果及首次提取正文按任务键暂存 24 小时；投标异步任务状态和初稿同步迁移，避免服务进程内存丢失已完成结果。
- 招标任务新增一次性自动修订接口：必须先完成首次审查；后台按首次审查结果修订初稿，重新执行确定性检查与第二次语义审查，并保留初始初稿、初始检查及首次审查结果供人工对照。
- 自动修订完成后更新 `currentVersionId`；每个任务最多执行一次自动修订，重复调用会明确拒绝。
- 招标任务新增 Redis 版本快照：AI 初稿、自动修订稿和人工编辑稿均保存版本元数据、Markdown、确定性检查与审查结果；版本包含父版本、序号、变更来源、修改人和定稿标记。
- 新增招标人工版本接口、版本列表接口与确认定稿接口；人工保存不会调用模型，确认定稿会切换任务当前版本并保证同一任务只有一个定稿版本。
