# DOCX 保守排版

对现有文件执行固定脚本，不改正文，不让模型临时重写排版代码。招标文件使用 `tender`，审核报告使用 `report`。

## 执行

1. 阅读 [排版规则](references/formatting.md)。确认待处理文件已存在；人工定稿内容是唯一正文依据。
2. 使用终端执行，输入与输出必须是不同路径，输出不能覆盖已有文件：

   ```bash
   python3 scripts/format_docx.py input.docx output.docx --kind tender
   python3 scripts/format_docx.py review.docx review-formatted.docx --kind report
   ```

   路径相对于本 Skill 目录。脚本自动使用 `/usr/bin/python3` 调用 UNO，超时默认 180 秒。不需要自行安装依赖。
3. 读取 JSON 结果及退出码。`success` 表示结构检查和目录检查通过；`partial` 表示目录被保留、没有计算真实目录；`fallback` 表示输出是原文件副本，排版没有通过。后两种不能声称排版完全成功。
4. 对成功文件渲染抽查封面、目录、正文首章、复杂表格和末页；结构校验不能证明视觉完全一致。发现内容或布局明显受损，交付原文件并明确提示，不尝试删除正文修复。
5. 仅对确定要交付的文件调用平台 `mark_artifacts`。两个阶段产物的数量、名称由业务系统提示词决定；本 Skill 不新增报告、说明页或待补充清单。只有获得 `file_id` 才能声称可下载。

## 不可突破的边界

- 不凭字号、加粗、标题文字或正则表达式猜章节；无可靠标题时不强造目录。
- 不删除疑似手写目录；边界不清时不再追加第二份目录。
- 不手写页码，不以“用户打开 Word 自行更新”替代真实目录验收。
- 保留原始文件。不能为了通过校验扩写、缩写、替换或移动正文。
- 禁止宏执行与外部链接自动更新；不上传文件到第三方服务。
- 没有 LibreOffice/UNO 时报告不可用，不编造成功结果。
